## 2026-06-11 — 角色门禁白名单化：顾问/执行分工确立

**现象**：顾问窗口通过 `python scripts/daily_signal.py` 绕过 Bash 门禁，Hook 未拦截。根因：命令无文件路径，`extractPaths` 返回空数组，`taskPaths.length === 0` 直接放行。

**排查路径**：
1. 假设：顾问无权跑 script → 验证：Hook 拦截逻辑有漏洞，空路径=放行 → 成立
2. 假设：用正则限制命令白名单 → 验证：审计驳回（`$` 锚定缺失、注入面）→ 废弃
3. 最终方案：从 000-guard-mcp 模板复制 pre_bash.js，使用 `ADVISOR_READONLY_CMDS` 数组 + `startsWith` 前缀匹配 → 审计通过

**修复**：`.claude/hooks/pre_bash.js` — 模板覆盖，v159

**教训**：
- 顾问/执行双窗口依赖 Hook 强制执行，Hook 漏洞 = 角色隔离失效
- 正则方案引入注入面，数组 + startsWith 零争议
- 空路径 ≠ 安全，必须验证命令本身

## 角色分工说明（确立于 2026-06-11）

### 两个窗口

| | 顾问窗口 | 执行窗口 |
|------|---------|------|
| 角色标记 | `role.json` → `advisor` | 不写 role.json（Hook 读 `.gate/role.json`） |
| 触发词 | `顾问` | `执行` |
| 模型 | 最强推理模型 | 轻量快模型 |

### 顾问窗口职责

- **信息检索**：读文件、查日志、git status/log/diff
- **分析决策**：审查 outcome.md，判断审计报告，定技术方案
- **任务调度**：写 direction.md 分派任务给执行窗口
- **文件写入**：仅 5 个白名单文件
  - `.claude/role.json`
  - `.claude/next-session.md`
  - `.claude/task/direction.md`
  - `.claude/task/outcome.md`
  - `.claude/task/recommendation.md`
- **禁止**：改业务代码、跑脚本、git commit/push、写项目日志

### 执行窗口职责

- **执行 direction.md**：逐项完成，不询问确认
- **写 outcome.md**：完成后汇报结果
- **所有实际操作**：跑脚本、改代码、git commit/push、写项目日志、发 release
- **保护区文件走 audit 流程**：validate → audit → 令牌放行

### 数据流

```
顾问窗口                    执行窗口
  │                           │
  ├─ 读代码/日志/状态         ├─ 读 direction.md
  ├─ 分析/决策                ├─ 执行任务
  ├─ 写 direction.md ────────→├─ 写 outcome.md
  ├←──── 审查 outcome.md ─────┤
  ├─ 写 recommendation.md     ├─ 写项目日志
  │                           ├─ git commit/push
```

### 为什么这样分工

决策责任不可外包。顾问做技术判断，执行做精确操作。Hook 在两层之间强制执行边界——顾问跑不了脚本，执行不自行判断。代价是流程绕一点，回报是零越界。
