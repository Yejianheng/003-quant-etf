### 全面核查 — 发现图表 cash 列 bug

**现象**：7/20~7/28 全现金期间，图表 `cash` / `repo_amount` 列显示 **0%**（应为 **100%**）。非现金时段正常。

**排查路径**：
1. 怀疑数据源 → 检查 parquet 和 records_df，数据无误
2. 怀疑信号计算 → `generate_signal()` 输出正确，final_multiplier 正常
3. 定位到显示层 → `nav_chart.py:364-365` 的 `cash = 1.0 - prev_final_mult`

**根因**：`scripts/nav_chart.py:364` — 全空仓时 `defense_active=[]`，`final_multiplier` 默认 1.0（语义："100% 分配"），导致 `1.0 - 1.0 = 0.0`。但 `final_multiplier=1.0` 在全空仓场景下的真实含义是"100% 进 repo"，不是"100% 买 ETF"。显示层误用了这个值推算现金比例。

**修复**：`cash` / `repo_amount` 改用 `1.0 - sum(weights.values())`。正常时段 `sum(weights)` = `prev_final_mult`（等价旧逻辑）；全空仓时段 weights 全 0 → `1.0 - 0 = 1.0`（修复）。

**教训**：`final_multiplier` 在 `defense_active=[]` 时的语义是"资金分配率"而非"仓位率"——100% 分配给了 repo。显示层反推现金比例应直接用 `sum(weights)` 而非 `1.0 - final_multiplier`。同理，任何需要区分"满仓 ETF"和"满仓 repo"的场景都不能仅靠 `final_multiplier` 判断。

## 必读：final_multiplier 在全空仓时的语义陷阱

**规则**：当 `defense_active=[]`（趋势过滤剔除全部 ETF）时，`final_multiplier` 默认 = 1.0。这个 1.0 的含义是"100% 资金已路由到 repo"，**不是**"100% 买了 ETF"。

**陷阱**：任何用 `1.0 - final_multiplier` 反推现金比例的代码，在全空仓时会得到 0%（错误）。

**正确做法**：
```python
# 错误：全空仓时得 0%
cash = 1.0 - final_multiplier

# 正确：全空仓时 weights 全 0，得 1.0
cash = 1.0 - sum(weights.values())
```

**影响范围**：仅显示层（图表/报告）。策略计算中 `final_multiplier * weights` 的用法不受影响——因为 weights 本身已经是 0，乘积正确。
