## 07:30 — 9 月数据全面核查：511010 价格基准接缝

**现象**：执行 `仓位` 命令时，511010（国债ETF）的东财源 `_em` 对 5 只 ETF 全部连接失败，
降级为 tx+sina 双源。顺带核验 9 月数据，发现 511010 与两个独立源系统性对不上，
而其余 4 只完全一致。

**排查路径**：

1. 假设：9 月漏采交易日 → 用上证指数 `sh000001` 独立取交易日历
   - 9 月 19 个交易日：`09-01~04, 07~11, 14~18, 21~24, 28`
   - 09-25 为中秋休市，5 只 ETF 日期集合完全一致
   - **排除**：日历无误。

2. 假设：OHLCV 某列有问题 → 逐列对照 tx / sina 两源（19 行）
   - 510300 / 159915 / 513100 / 518880：open/high/low/close/volume **全部 0 行不匹配**
   - 511010：open/high/low/close 各 9 行不匹配 tx、4 行不匹配 sina
   - **成立**：问题仅限 511010，且只在部分行。

3. 假设：接缝（数据源切换）而非单日错价 → 拉全历史 3199 行比对
   - parquet 与 **sina 精确相等 3193/3199 行**（2013-07-31 → 2026-09-11）
   - parquet 与 **tx 精确相等仅 10 行**（2026-09-14 起）
   - 分界点 = **2026-09-14**，两侧相差恒定 **0.441%**
   - **成立**。

4. 假设：影响熔断信号 → 用 `correlation_circuit_breaker` 三种口径各算一遍
   - 现状（混合基准，错误）：smoothed=+0.0608 → **触发**
   - 统一 sina 原始价：smoothed=−0.1274 → 不触发
   - 统一 tx 前复权：smoothed=+0.0464 → 触发
   - **成立**：现状不等于任何一种自洽口径。

**根因**（已用 `git show HEAD:data/511010.parquet` 验证）：

接缝是**本次 `仓位` 命令自己造出来的**，不是历史遗留。

- HEAD 版：3189 行，**末行 2026-09-11**，收 141.146（sina 原始价基准，无接缝）。
  本次新增 **10 行：2026-09-14 ~ 2026-09-28**（5 只 ETF 均同）。
- 生成链条：
  1. `update_data.py:74` — `start = last_date + 1天` = 09-12，**纯追加**，旧行永不重写。
  2. 三源同拉 09-12~09-28。`data_pipeline.py` 中 **tx 用 `adjust="qfq"`（前复权）**、
     **sina 用 `ak.fund_etf_hist_sina`（原始价，接口不支持复权）**。
  3. `update_data.py:113` — `preferred = next(s for s in ["tx","em","sina"] ...)`，
     **tx 优先级最高 → 选中前复权数据**。
  4. 511010 于 **2026-09-18 除息**。前复权以最新价为锚、按累计分红下调历史，
     于是 tx 把 **09-14~09-17 也一并下调 0.441%**（140.553 = 141.173 × 0.99561）。
  5. 追加写入 → 旧行（≤09-11）留在 sina 原始价基准，新行（≥09-14）落在 tx 前复权基准。
     09-12/13 是周末，**新增段第一个交易日正是 09-14** —— 这就是接缝为何落在这一天。
- 为何 09-18 之后又对上了：前复权在"最后一次除息之后"那一段等于原始价，
  故 09-18~09-28 的 tx 值 == sina 值，接缝只在 **09-14~09-17 四天**可见。
- 为何只有国债ETF 出事：另 4 只在该窗口内**无分红**，tx 前复权 == sina 原始价，接缝为 0。
- 具体表现：09-18 真实除息跌幅 **−0.41%** 被抹平，同时在 **09-14 凭空记 −0.4201%**
  （tx +0.0192% / sina +0.0191%，两源一致确认真实为 +0.02%）。
- **危险性质**：接缝两端（09-11 与 09-28）都在同一基准上，**区间总收益正确**
  （−0.3563%，与 sina 一致），只有中间 4 天的日内路径是错的。
  **区间对账查不出来**，靠逐日比对或信号异常才发现。
- 触发条件（复现所需）：(a) 两次更新之间发生分红除息；(b) 三源可用且 tx 被选中。

**影响**：

1. `correlation_circuit_breaker` 输入被污染 → 9 月熔断判定翻转（见上方三口径）。
   熔断平滑相关性 09-22 由负转正（+0.0159），09-22 起持续为正。
2. `nav_2026.html` 09-14 净值：当日持有 [沪深300/纳指/黄金/国债ETF] 各 25%，
   国债 25% × 0.439pp 虚假跌幅 = **净值少算约 0.11pp**，误差此后一直保留。
3. 其余 4 只 ETF 与 511010 除 09-14~09-17 外的 9 月数据**均准确**。

**修复**：未修复（待定口径）。修复路径涉及价格基准口径决策（原始价 vs 前复权），
影响全历史回测，须走 direction.md → validate → audit。

**教训**：

1. **"全历史同源"是隐性不变量，且增量追加会打破它。** 库里 3199 行一直由 sina 原始价
   构建；`start = last_date + 1天` 的纯追加逻辑意味着**旧行永不被重写**，
   所以一次跨除息的追加就能把两种口径缝在同一条序列里。
   **危险在于区间总收益是对的**——区间对账、跨源校验（只比最新一日）都查不出来。
   防御办法：追加前先重拉**最后一行**并与库存值比对，不一致即基准已变，必须报警。
2. **主源优先级 tx > em > sina 与"库内历史口径"从未被对齐过。** 选择主源时只看
   当日收盘价是否一致（`groups` 按 close 分组），**完全没考虑复权口径**。
   只要收盘价碰巧一致就选 tx，而 tx 是前复权。这是本次事故的直接入口。
2. **原始价与前复权价不可混用。** 二者在除息日的行为相反（原始价跳水、前复权平滑），
   混用会同时产生一记虚假跌幅和一处被抹平的真实跌幅，净额抵消、极难发现。
3. **历史遗留行需单独标注。** 5 只 ETF 各有 1~2 行（`2026-06-11` / `06-16` / `2026-07-03`）
   与两源均不吻合，偏差 0.02%~0.05%，疑似 v217 期间 Web 核验手工入库行，本次未处理。

## 07:45 — 仓位报告「全部清仓」指令与图表矛盾（接缝污染熔断，图表画了假清仓）

**现象**：`仓位` 命令输出 `【操作指令】全部清仓（熔断触发）`，
且「当前持有」段报 `持有：纳指、黄金（2 只等权）`。
但图表 `nav_2026.html` 显示 09-23 起已 100% 现金（逆回购）。两者矛盾。

**排查路径**：

1. 假设：其中一方取错字段 → 用 `generate_signal` 逐日截断复算（数据截止各日收盘）
   - 09-21 信号 → 09-22 持仓 {创业板/纳指/黄金} 各 1/3 ✓
   - **09-22 信号 → 09-23 持仓 = 全现金（cb=True, mult=0.0）** ✓
   - 09-24 / 09-28 信号 → 次日均为全现金 ✓
   - **成立（就现状数据而言）**：图表符合"T 日持仓 = T-1 信号"口径。
     但"现状数据"本身已被接缝污染——此路只证明了内部自洽，没证明谁对。

2. 假设：熔断触发日受接缝影响 → 三种口径各算一遍触发日
   - A 现状（混合基准，错误）：**09-22 触发**
   - B 原始价（与 2013 年至今全历史一致）：**9 月从未触发**
   - C 前复权（自洽但需重跑全历史）：09-01 起持续触发
   - **成立**：触发与否完全取决于口径；A 不等于任何一种自洽口径。

3. 假设：按自洽口径重跑回测，看真实应有的持仓与净值 → `run_backtest(execution_lag=1)` 跑两遍
   - 现状：09-22 触发 → 09-23 起全现金 → 归一净值 **1.0378**
   - 修正（B）：熔断不触发 → 09-23~09-24 持 创业板;纳指;黄金，09-28 持 纳指;黄金
     → 归一净值 **0.9955**
   - **成立**：正确数据下**根本不该清仓**。

4. 假设：报告「当前持有」的推导方式是否可靠 → 读 `check_position.py:116`
   - `held = prev_signal["defense"]["active"]` —— `active` 是**趋势过滤幸存名单**，
     不含熔断。熔断触发时 `final_multiplier=0`、`funds_to_repo=True`，实际持仓是现金
   - **成立（但本次结论需修正）**：该推导方式不可靠，
     但本次它恰好等于正确答案——因为修正后真实持仓本就是 纳指+黄金，
     且 纳指/黄金 不受国债接缝影响。
   - 操作指令侧另有缺陷：`daily_signal.py:378` `_prev_active_signal` 构造基线时
     写死 `"circuit_breaker": {"triggered": False}`；`_compare_signals` L214
     `if current["circuit_breaker"]["triggered"]: return ["全部清仓"]` **只看 current**。
     只要当日熔断触发就**恒输出「全部清仓」，哪怕昨日已清仓**——与 v221 修的
     「恒输出无需调仓」是同族 bug，方向相反。

**根因**：

- 数据面：见上一条记录，511010 接缝污染股债相关性 → 熔断误触发（A 口径）
- `scripts/check_position.py:116` — 用 `defense["active"]` 冒充持仓
- `scripts/daily_signal.py:378` — 基线硬编码 `triggered: False`
- `scripts/daily_signal.py:214` — 熔断分支无 previous 判定

**影响**：

1. **图表画了一次本不该发生的清仓**。持仓段 09-23~09-28 应为
   {创业板;纳指;黄金}→{纳指;黄金}，而非现金。
2. **报告「全部清仓」是错误指令**；其「当前持有：纳指、黄金」恰好命中正确答案。
3. **反直觉**：错误数据反而让净值更高（1.0378 vs 正确 0.9955）——
   误打误撞在 09-23 清仓，躲过了 09-24 与 09-28 的下跌。
   这是运气不是策略，不能作为"不修"的理由。
4. 接缝还改变了 09-15 起国债ETF 的趋势过滤结果，持仓路径级联偏离。

**修复**：未修复。需先定价格口径（本条第 1 项），再修 `scripts/` 两文件与数据。
须走 direction.md → validate → audit。
测试方向：`tests/test_signal_gap.py` 需新增「熔断已持续多日 → 报无需调仓」用例；
「当前持有」需按 `funds_to_repo` 判定而非 `active`。

**教训**：

1. **"内部自洽"不等于"正确"。** 第 1 步证明了图表符合 T-1 口径，差点就此收工——
   但被污染的数据算出的自洽结果依然是错的。**必须再问一句"输入数据本身对吗"**。
2. **`active` 不是持仓。** CLAUDE.md 已记载 `final_multiplier` 在全空仓时的语义陷阱，
   本次是同一陷阱的另一张脸：熔断清零时 `active` 依然非空。任何从 `active` 反推
   "持有什么"的代码都必须先过熔断/乘数闸门。
3. **比较函数的两边都要读。** `_compare_signals` 的熔断分支只读 `current`，
   使 previous 完全失效——这类"单边判断"会让增量指令退化成无条件指令。
4. **口径决策会级联改变一切。** 熔断是价量型、路径无关的，但一旦触发，
   现金/持仓的分野会让净值、回撤、后续乘数全部偏离。修数据前必须先定口径。
