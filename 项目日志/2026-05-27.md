**根因**：项目初始化时创建了 `settings.hook.json` 模板，但没有执行合并步骤。hooks 从未被调用，三层防护形同虚设。

**修复**：

**修复中发现的次级问题**：
- `pre_bash.js` 的 `isWriteOrDelete` 将 `2>&1`（标准 stderr 重定向）误判为文件写入 → 在检测前加 fd 重定向清洗：`cmd.replace(/\d+>&?\d*/g, "").replace(/&>/g, "")`

- Edit 工具的分段编辑不共享令牌（每段 newStr 需独立包含 `@claude-override-approved`）

## 教训

1. **VPN 代理残留**：关闭 VPN 客户端 ≠ 清除代理。`ProxyServer` 注册表项残留，`requests` 通过 `get_environ_proxies()` 读取。修复方案：monkey-patch `Session.__init__` 设 `trust_env=False`。
2. **东方财富限流**：K 线 API 有严格 WAF，短时间多次调用触发断连。已通过 pre_bash.js 分时限流 + data_pipeline.py 重试解决。
3. **pandas index 对齐陷阱**：构造测试数据时，Close Series 需先设 DatetimeIndex 再放入 DataFrame，否则整数 index vs DatetimeIndex 对齐全部生成 NaN。教训：测试 helper 必须返回正确 index 的 Series。
4. **顾问-执行协作模式**：10 步开发中顾问写 direction → 执行编码 → 顾问审查 → commit，每步 5-10 分钟。整体运行流畅。
5. **settings.hook.json 模板陷阱**：模板文件不等于生效配置。`settings.hook.json` 写了 "合并到 settings.json" 但项目初始化时未执行，导致三层 hook 从未触发。教训：初始化后必须验证 hook 确实在运行（如用无害命令测试拦截行为）。
6. **\d* 正则陷阱**：`\d*>&?\d*` 中的 `\d*` 匹配零个数字 → 裸 `>` 被匹配 → 文件写保护全部失效。这是本日最严重的 bug——它让 Bash 文件保护完全空转。`\d+` 才是正确的（至少匹配一个数字，只匹配 `2>&1` 类的 fd 重定向）。
7. **Python 命令行中文编码**：Windows bash 传递含中文的命令行参数给 `python -c` 时编码会损坏。涉及中文路径的关键操作应使用 Node.js（`fs.writeFileSync` 原生支持 UTF-8）。
8. **Edit 工具分片不共享令牌**：每次 Edit 的 `newStr` 独立检查。如果第一个 Edit 修改注释头（含令牌），第二个 Edit 修改函数体（不含令牌），则第二个会被拦截。解决方案：合并到一次 Edit 或在每段 newStr 中嵌入令牌。
