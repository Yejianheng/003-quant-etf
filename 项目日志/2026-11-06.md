# 2026-11-06

## 21:30 — 断层回放误报持仓与幽灵买卖（仓位报告与图表不一致）

**现象**：
- 执行「仓位」命令（自 10-23 空档后首次运行），报告输出「当前持有：国债ETF、纳指（2 只等权）」、
  「操作指令：全部清仓（熔断触发）」，期间回顾列出 11-03 卖出纳指、11-04 买入纳指、11-06 卖出纳指。
- 用户指出 `nav_2026.html` 11 月没有任何操作。
- 实际：相关性熔断自 2026-07-03 起持续触发，`final_multiplier=0.0`，账户自 7-03 清仓后一直 100% 逆回购。
  图表正确，文字报告错误。

**排查路径**：
1. 图表 HTML 内嵌 tableData 逐日核对 → 11-02 ~ 11-06 权重全 0、现金 100%、明日调仓「无需调仓」；
   最后一笔真实交易 2026-07-03 全部清仓。成立。
2. 回测 `records_df` 核对 → `circuit_breaker_triggered` 自 2026-07-03 起连续 True，
   `final_multiplier` 恒 0.0。成立。
3. 上次 state（HEAD，last_date=2026-10-23）中 `last_cb_triggered: true`、`last_final_multiplier: 0.0`。
   说明错误来自回放路径，而非 state。成立。
4. 读 `scripts/daily_signal.py` → `_replay_gap` 只按 `trend_strength` 回放，
   完全不读熔断/乘数；`_prev_active_signal` 合成断层基线时硬编码
   `circuit_breaker.triggered=False`，丢弃 fallback state 的真实熔断状态。定位完成。

**根因**：
- `scripts/daily_signal.py` `_replay_gap()`：趋势回放路径不消费回测引擎的
  `circuit_breaker_triggered` / `final_multiplier`，把趋势翻转直接当买卖事件 → 幽灵交易。
- `scripts/daily_signal.py` `_prev_active_signal()`：断层回放基线硬编码熔断为 False，
  导致 `held_names()` 用趋势幸存名单冒充持仓（报「持有 2 只」），
  `_compare_signals()` 误判「昨日未熔断、今日熔断」→ 重复报「全部清仓」。
- 该错误路径仅在断层 ≥2 个交易日时触发（此时基线由回放合成）；单日运行时读真实 state，
  所以平时不暴露。本次 10-23 → 11-06 长空档首次踩中。

**修复**：
- `scripts/daily_signal.py`：
  - `_replay_gap(prices, state, records_df=None)` 新增可选 `records_df`；
    传入时逐日读取引擎 `defense_active` / `circuit_breaker_triggered` / `final_multiplier`，
    `held = ∅`（熔断或乘数归零），changes 基于 held 计算并带 `reason`（熔断/趋势）。
  - `_prev_active_signal()` 基线改用回放日的 `held`，保留 `circuit_breaker` 与 `final_multiplier`。
  - `_format_replay_segments()` 按 held 展示；熔断持续期输出「空仓（熔断中），无变化」，
    熔断切换输出「全部清仓（熔断触发）」/「熔断解除，买入 …」。
  - 新增 `_build_backtest()` 同时返回净值与 records；`_build_portfolio_value()` 保持兼容。
  - `_compare_signals()` 改用 `_effective_holdings()`（熔断/乘数归零视为空仓）。
- `scripts/check_position.py`：改调 `_build_backtest()`，并把 records 传给 `_replay_gap()`。
- `tests/test_signal_gap.py`：新增 7 条红灯测试（回放熔断状态、期间回顾、基线熔断标记、
  check_position 集成），修复前全部复现事故输出，修复后全绿。
- 验证：用 HEAD 的 10-23 旧 state + 真实数据回放 → 「2026-10-23 → 2026-11-06 空仓（熔断中），无变化」，
  当前持有空仓，操作指令「无需调仓（熔断持续）」。

**教训**：
- 文字报告与图表必须同源。图表基于回测引擎 records，报告却另算一套趋势回放 ——
  两套口径必然迟早打架。以后任何「持仓/操作」输出，一律以引擎 records 为准。
- `defense.active` 只是趋势幸存名单，不是持仓。熔断、`final_multiplier` 任一归零都必须显式折算。
- 断层回放这类「低频路径」最容易藏 bug：只在长时间未运行后触发，日常单日运行测不到。
  新增测试必须覆盖 gap ≥ 2 且熔断持续的场景。
