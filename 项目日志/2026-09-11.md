# 2026-09-11

## 21:15 — 仓位报告「操作指令」恒输出"无需调仓"（v221 修复）

**现象**：跑 `仓位` 命令，报告输出：

```
【操作指令】
  无需调仓
```

但图表 `nav_2026.html` 最后一日（09-11）画的是 4 只持仓（沪深300、纳指、黄金、国债ETF 各 25%），
而报告的「当前持仓」段列的是 3 只（纳指/黄金/国债ETF 各 33.3%）。两处对不上。

按趋势强度反查，09-11 沪深300 的 trend_strength 由 +0.217（09-10）转负为 -0.555（09-11），
说明当日确实发生了趋势变化，报告却报"无需调仓"。

**排查路径**：

1. 假设：图表画错了 → 逐日核对 `tableData` 的 weights 与各 ETF 趋势强度
   - 09-10 行 weights=[0,0,.333,.333,.333] ← 对应 09-09 信号（沪深300 趋势 -0.787，剔除）✓
   - 09-11 行 weights=[.25,0,.25,.25,.25] ← 对应 09-10 信号（沪深300 趋势 +0.217，纳入）✓
   - **排除**：图表符合"T 日持仓 = T-1 信号"口径，画得对。

2. 假设：报告的操作指令基线取错 → 读 `check_position.py` L100-109
   - 发现 `prev_signal = daily_active[-1]["active"]`
   - `daily_active[-1]` 是 **T 日**信号（= 次日目标），而 T 日实际持仓应为 **T-1** 日信号
   - **成立**。

3. 假设：该 bug 只在当日有趋势变化时发作 → 模拟复现
   - 模拟 09-10 收盘运行：应报「买入 沪深300」，实际报「无需调仓」✓
   - 模拟 09-11 收盘运行：应报「卖出 沪深300」，实际报「无需调仓」✓
   - **成立**：基线取 `daily_active[-1]` 时 prev==curr，恒等于"无需调仓"；
     而原代码还套了 `if replay_result["changes"]` 前置条件——**恰恰只在有变化时进入该分支**，
     即每次发作都在最需要指令的那天。

4. 假设：不止一处 → grep 同样模式
   - `scripts/daily_signal.py` 的 `format_signal_report` 里有一段完全相同的复制粘贴代码
   - **成立**：两处都要修。

**根因**：
- `scripts/check_position.py` L100-109（旧行号）
- `scripts/daily_signal.py` `format_signal_report` 内联分支
- 两处均取 `daily_active[-1]` 作为对比基线，与图表"T 日持仓 = T-1 信号"口径冲突。

**修复**：
- `scripts/daily_signal.py` 新增 `_prev_active_signal(replay_result, fallback)`：
  - gap ≥ 2 → 取 `daily_active[-2]`（T-1 信号 = T 日实际持仓）
  - gap ≤ 1 → 原样返回 fallback（state 中保存的上一交易日信号）
  - 两者皆无 → None（首次建仓）
- `scripts/daily_signal.py` `format_signal_report` 换用该函数，删除内联重复逻辑
- `scripts/check_position.py` 同上；并将持仓段拆为
  「当前持有」（T-1 信号）+「次日目标仓位」（T 信号）——原「当前持仓」标题显示的实为次日目标
  （T-1 那天的仓位乘数未持久化，故「当前持有」只报名字，不编百分比）
- 测试：`tests/test_signal_gap.py` 新增 `TestPrevActiveSignal`(5) + `TestReportActionBaseline`(3)；
  `tests/test_check_position.py` 新增 `TestActionBaselineIntegration`(2)

**顺带修掉的既存失败**：`TestCheckPosition` 4 条 + `TestCheckPositionReplay` 1 条在 HEAD 上就是红的。
根因是 `update_single_etf` 被裸 `MagicMock()` 桩住 → `r.get("needs_verify")` 为真值 →
脚本误入「待核验」分支 → 格式化 MagicMock 抛 TypeError 提前 `sys.exit`。
改用桩返回值 `{"ok": True, "needs_verify": False}`（`nav_chart.py` 同因，一并修）。

**教训**：

1. **"自己跟自己比"的对比逻辑，测试必须覆盖"两边不同"的用例。** 这个 bug 的两个副本能长期存活，
   是因为没有任何测试断言过"趋势变化日必须报出买卖"——已有测试只断言报告含「操作指令」段落，不看内容。
2. **回放数组的索引语义要写进 docstring。** `daily_active` 的元素是"该日收盘算出的信号"，
   它对应的是**次日**持仓。取"当前持仓"必须 `[-2]`。这类 off-by-one 靠读代码很难发现，
   靠"和图表对不上"才暴露——**图表是当前唯一的交叉验证手段**。
3. **先跑测试基线再动手。** 本次若不是先跑 HEAD 基线，会把 5 条既存失败误判为自己引入的回归。
   新建基线这一步值得固化成习惯。
