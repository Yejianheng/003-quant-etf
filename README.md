# 003-quant-etf

ETF 多资产动量轮动量化系统。AI 辅助纪律执行和标的筛选。核心矛盾——人不会代码因此必须依赖 AI 做技术判断——决策责任不可外包。

---

## 策略概要

**纯防御 ETF 动量轮动**（进攻层已搁置）。五只防御标的（沪深300、创业板、纳指、黄金、国债ETF），日频信号链：

```
趋势过滤（Trend Strength > 0）→ 等权分配 → EWMA 协方差 → Vol Target 缩放
    ↓
相关性熔断（股债正相关则全仓 repo）
    ↓
回撤硬止损（-8% 减半 / -12% 警告 / -18% 清仓）
    ↓
最终敞口 = min(vol_scaling_factor, drawdown_multiplier, circuit_breaker_multiplier)
```

完整策略规格见 [方向性讨论.md](方向性讨论.md)。完整测试证据见 [测试报告.md](测试报告.md)。

## 核心参数

| 参数 | 值 | 说明 |
|------|-----|------|
| trend_window | 40 | 趋势判断窗口（T+1 下 40 回撤最优，20/120 各有取舍） |
| **target_vol_beta** | **0.18** | **目标波动率（T+1 可执行基准下约束最优，边际换率 1.50）** |
| vol_tolerance | 0.027 | 容忍带（= beta × 15%，等比缩放） |
| ewma_lambda | 0.94 | RiskMetrics 标准（全区间 0.85-0.99 ΔSharpe<0.02，确认鲁棒） |
| corr_threshold | 0.0 | 任何正相关即熔断（T+1 下回撤保护 3.7pp） |
| defense_ratio | 1.00 | 纯防御（进攻层搁置） |
| drawdown 三级 | 8% / 12% / 18% | 减半 / 警告 / 清仓（12 年零触发 liquidate） |

> **T+1 可执行基准**：全量扫描统一为 execution_lag=1（现实可行，不含 1 日先知优势）。之前 T+0 数据（T 日收盘既算信号又成交）物理不可执行，作废。

全部参数受 Hook 保护（`protected-contracts.json`），篡改需走 audit 流程。

### 参数选择：为什么是 0.18 不是 0.15

**0.15 是基于 T+0（物理不可执行）数据选定的，依据作废。** T+0 下 T 日收盘价既算信号又成交，含 1 日先知优势（ΔSharpe ~0.17）。全量扫描切换到 T+1 可执行基准后重跑：

| beta | 年化(T+1) | 回撤(T+1) | Sharpe(T+1) | 边际换率 | 备注 |
|------|------|------|------|------|------|
| 0.08 | 10.3% | -9.9% | 1.14 | — | 最保守 |
| 0.10 | 10.7% | -11.2% | 1.11 | 0.31 | |
| 0.12 | 10.9% | -12.4% | 1.08 | 0.17 | |
| 0.15 | 11.1% | -13.6% | 1.06 | 0.17 | 旧生产参数（基于 T+0） |
| **0.18** | **11.4%** | **-13.8%** | **1.06** | **1.50** | **新生产参数（T+1 约束最优）** |
| 0.22 | 11.5% | -14.1% | 1.06 | 0.33 | 边际衰减 |

**0.15→0.18 边际换率 1.50**（全扫描最高）：每 1% 回撤换 1.50% 年化。回撤 -13.8% 距 20% 硬约束仍有 6.2pp 安全垫。T+1 数据在 v190-20260618-29 完成全量重扫，0.18 替代 0.15 成为可执行基准下的约束最优。

## 协作模式

双窗口角色分工，Hook 强制执行边界。

### 顾问窗口（触发词：`顾问`）

- 信息检索：读代码、查日志、git status/log/diff
- 分析决策：审查执行结果、判断审计报告、定技术方案
- 任务调度：写 direction.md 分派任务
- 写入权限：仅 5 个协议文件（role.json / next-session.md / direction.md / outcome.md / recommendation.md）
- 禁止：改业务代码、跑脚本、git commit/push

### 执行窗口（触发词：`执行`）

- 读 direction.md，逐项执行，不询问确认
- 写 outcome.md 汇报结果
- 所有实际操作：跑脚本、改代码、git commit/push、写项目日志、发 release
- 保护区文件修改走 audit 流程（validate → audit → 令牌放行）

### 数据流

```
顾问窗口                    执行窗口
  │                           │
  ├─ 读/分析/决策             ├─ 读 direction.md
  ├─ 写 direction.md ────────→├─ 执行任务
  ├←──── 审查 outcome.md ─────┤
  └─ 写 recommendation.md     └─ git commit/push
```

### 设计原则

决策责任不可外包。顾问做技术判断，执行做精确操作。Hook 在两层之间强制执行边界——代价是流程绕一点，回报是零越界。

## v188 — 50/50 A/B 策略落地（2026-06-16）

### 策略机制

50/50 A/B 组合：A端满仓（不受波动率缩放）+ B端缩仓（sf+0.08），等效单策略乘数：

```
final_multiplier = (dd_mult + min(sf, dd_mult)) / 2
```

- 低波动（sf ≥ dd_mult）：= dd_mult，满仓运行
- 高波动（sf < dd_mult）：= (dd_mult + sf) / 2，半保护

### 六步决策链

1. 趋势过滤（trend_strength > 0）→ active ETF 池
2. 等权分配
3. EWMA 波动率缩放（target_vol_beta=0.08）
4. 股债相关性熔断（corr_threshold=0.0，>0全线清仓）
5. 回撤硬止损（三级：8%/12%/18%）
6. 资金路由（50/50乘数 × 等权权重）

### 策略选择理由

纯B Sharpe 1.205 更高但牛市被sf拖累收益。50/50在低波动时不受sf限制（等于纯A满仓），高波动时获得一半保护。不是数学最优，是实用最优。

### v186 — 50/50 A/B 组合策略（2026-06-12）

- **方案**：50% A（无 sf）+ 50% B（sf+0.08），各自独立不调仓
- **效果**：Sharpe 1.108，年化 10.47%，回撤 -9.66%——比纯 B 多赚 1.4 点年化，比纯 A 少亏 4.3 点回撤
- **原理**：不调仓自带"牛熊自动切换"——牛市长得快的策略占比自动变大，熊市亏得猛的占比自动缩小
- **等效单策略**：乘数 = (dd_mult + min(sf, dd_mult))/2，低波动满仓、高波动半保护
- **图表**：`nav_full_2014_2026.html`、`nav_2026.html` 三策略对比
